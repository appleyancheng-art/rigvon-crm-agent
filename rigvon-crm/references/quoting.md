# 报价配置与图纸盘点

用于“做一份报价”“根据 PDF 配设备”“调整方案配置”等任务。目标是理解空间与控制需求，选出能配套使用的库内产品，把数量和分组交给 CRM；成本、毛利、服务费和总额由 CRM 计算。用户本次明确要求优先于本指南的默认偏好。

## 先确定输入与交付范围

读取用户提供的图纸、需求、已有客户/报价；识别项目类型、楼层、面积、所需系统、品牌/外观/协议偏好和预算。预算用于控制方案范围和档次，不要求填满预算。只追问会影响方案的关键缺项，其余可用明确标注的假设继续初步报价。

- 有图纸：先做逐空间盘点，再汇总系统配置。文字需求与图纸冲突时指出具体页码和冲突，不静默选一方。
- 无图纸：按户型、空间、控制需求和适用模板给出“初步配置/预估数量”；不能因为缺图停止所有工作，也不能声称已精确测量。
- 修改已有单据：先读取原结构、设备、参数与版本，保留未要求改变的内容。只让分析或提建议时不落单；要求制作报价时可在授权范围建立草稿。客户未明确时先搜索，仍无法定位可使用服务器支持的临时报价流程，不虚构客户资料。

## 读取系统偏好，避免每次全库扫描

先搜索 templates 并读取适用模板，再查询 products 核对当前产品。必要时读取少量近期同协议、同项目类型、同范围的报价，参考搭配和分组；不要把第一页当全库，不需要每做一单都遍历所有历史单。

历史草稿和复制版本不是成交记录。参考同一项目的多个版本时避免重复加权；系统报价与灯具报价要分开比较。历史高频型号只是检索线索，不能证明兼容性或当前在售。

2026-11-16 核对的系统习惯：

- 有明确分组的报价常用“系统模块、智能面板、传感器、智能窗帘、线材”，按范围扩展网络、监控、灯具等；另有按楼层组织的别墅单。旧单也有不分组情况，但新建报价优先采用用户明确的系统分组偏好，不机械复制旧单未分组的状态。
- “150平方内-纯国产”是现有模板检索线索：配电箱、KNX 总线电源、24V 辅助电源、DALI 模块、融合网关、开合帘电机、存在传感器、智能面板及 EIB/DALI/三芯线材。名称不代表模板已设置面积匹配条件；读取实际 houseType、areaMin/areaMax、设备与数量规则后判断适用性。
- 模板与常见历史搭配涉及玛德克配电箱、HDL/ABB 电源与 DALI 设备、明纬辅助电源、世聪/HDL 面板、Creatrol 存在传感器、HDL 开合帘电机和轨道。网络/安防/暖通等按项目另配。它们是候选方向，不是必须采购的品牌清单；当前型号、启用状态、规格以实时产品库为准。
- 模板数量是起点，不是每套住宅的固定数量。不要照搬固定面板只数、传感器个数、轨道或线材米数，也不要按面积同比放大所有设备。

## PDF 与图纸：先盘点，再选型

使用当前客户端实际支持的 PDF 阅读、页面渲染/视觉工具。扫描图和符号不能只靠文字抽取；查看相关页、图例、标注和局部细节。没有看图工具或附件打不开时明确说明，继续已知需求的预估方案，并请求可读图纸，不宣称已分析图纸。CRM MCP 的普通业务附件上传不等于具备 PDF 解析能力，不为读图擅自上传至其他服务。

1. 列出图纸页码、图名、楼层、版本及用途（平面、开关、照明、窗帘、弱电等）。旧版、详图和同一区域重复表达不能累计成额外设备。
2. 识别实际空间、入口、床头、主要动线、窗位和设备位置；区分业主新增、已有保留、第三方提供和本次不含的范围。
3. 按图例逐页盘点，维护一份空间明细：`楼层/空间｜功能/位置｜数量与单位｜图纸页码/标注或推算依据｜图纸明确/建议配置/待确认｜目标报价分组`。不把三个证据等级混为一谈。
4. 关键符号模糊或缺少尺寸时提出针对性确认；可先输出预估数量或范围及假设。需要落单时选择明确说明的暂估值，不能把不确定项默默记为零或伪装精确。

### 面板与开关

- 区分一块面板、按键数、控制回路、控制位置及联排外框，不把四键面板算成四块，不把双控的两个操作位置当作两套负载。
- 有点位图按标注统计；只有平面图时按入口、床头两侧、走廊/楼梯、离家/回家场景等实际需求建议控制位置，并标明“建议配置”。不采用每个房间固定一块面板的规则。
- 根据每个位置需要的灯光、场景、窗帘和暖通控制确定键数/面板类型。场景键与回路不一定一一对应，不能按灯具只数直接推出按键数。
- 成套面板须核对本体、摇板、外框、颜色、联数及是否已包含底座；产品本身是套装时不重复添加部件。暖通面板和空调网关承担不同功能，不能相互替代。

### 灯光与系统模块

- 分别盘点顶面灯具、顶面灯带和柜体灯带；灯具按只、灯带按米，区分开关、调光、调色温及分区/回路。
- 先得到负载与控制回路表，再选执行器、DALI 网关/模块、恒流或恒压驱动及电源。按产品资料核对协议、电压、电流/功率、通道、地址/组容量和安装空间；资料不足就列为待核实，不给出虚构额定值。
- 不按一盏灯配一个执行器，不对已有内置驱动的成套灯具重复配驱动，也不默认所有灯共用一个驱动。灯具、驱动、低压电源和控制模块按实际拓扑分别核对。
- 配电箱按模块占位及合理余量选择；总线电源、24V 辅助电源按实际设备需求选配。融合网关/HomeKit/Matter 网关先核对功能重叠，不因历史出现多个网关就全部叠加。
- 本指南中的 KNX 模板用于相应系统；用户要求其他协议时按该架构选型，不强加 KNX 配电箱、960mA 电源或固定品牌。

### 传感器、窗帘和其他系统

- 传感器：依据空间用途、活动/静止存在需求、安装方式、遮挡及已知覆盖范围建议数量。开放空间可合并覆盖，但不能默认一只覆盖整层，也不默认每间必须一只。
- 窗帘：区分开合帘电机与卷帘电机，分别盘点窗位、纱/布层、独立轨道和控制组。左右对开两片布不当然等于两台电机；纱帘与布帘独立控制、异形/超长轨道等按方案另核。轨道按图示尺寸/可验证比例估算；只有窗宽时说明其与轨道长度可能不同，无尺寸不编造精确米数。
- 暖通：核对设备品牌、系统形式、内机/分区数量、控制协议和用户需求，再选择接口、网关与温控面板，不按卧室数推定空调内机数。
- 网络/监控/影音：按楼层、覆盖、墙体、点位和功能选配 AP、交换机/PoE、摄像机/存储等，未提出的系统不为凑预算默认加入；端口和功率等以真实规格为准。
- 线材：按所需协议、负载、走线路径和尺寸估算长度与余量；无走线图时单独标明估算依据及现场复核项，不能把模板米数当图纸实测。

## 空间盘点与 CRM“房间”分组是两层

实际房间用于算清楚需求；CRM 的 QuoteRoom 在这里主要用于报价分项。新建默认顺序：**系统模块 → 智能面板 → 传感器 → 智能窗帘 → 线材**，只创建实际有项目的分组。

按项目需要增加灯具与驱动（规模较大时拆顶面灯光、柜体灯光、DALI 驱动）、空调模块、网络覆盖、安防监控、全宅影音等。扩展系统通常放在线材之前；用户指定顺序或已有分组时沿用。独立灯具报价与整套系统报价按用户范围决定，不强制拆单或重复包含设备。

| 报价分组 | 常见归属 |
|---|---|
| 系统模块 | 配电箱/机柜、总线及辅助电源、执行器、系统网关、接口、DALI 控制模块 |
| 智能面板 | 按键面板、触控面板、暖通面板及对应成套配件；较大暖通范围可按用户要求单列 |
| 传感器 | 存在、移动、环境等传感设备 |
| 智能窗帘 | 开合帘/卷帘电机、轨道、相应配件；保留各自型号和计量单位 |
| 灯具与驱动 | 灯具、灯带及直接配套的灯光驱动/电源；不要与系统模块重复列入 |
| 线材 | EIB/KNX、DALI、回路线等对应系统线缆与辅材 |

这些是报价分组，不等于产品库 category；不为分组擅自批量改产品库分类。历史“电动窗帘/智能遮阳/窗帘系统”“通讯线材/总线线材”等可理解为相近分组；修改旧单不自动重命名。

别墅先按楼层盘点，再按用户选择输出楼层或系统。现有 QuoteRoom 是平级结构，没有嵌套房间：需要两种维度时可用“1F·智能面板”“1F·传感器”等平级名称；公共机柜/网关可单列“系统模块”。保留楼层顺序，不把同款设备跨楼层强制合并，也不重复计算公用设备。

同分组、同 productId、同规格/计量单位、同单价/折扣/服务费属性且没有需要保留的区别备注时，可合并数量；不要实施全单 productId 唯一限制。真实空间数量与报价汇总数量须能互相追溯，必要时以简短位置说明或独立盘点表保留。

## 落单与计价边界

1. 先完成空间盘点与拟选设备表，再创建草稿，减少边想边加产生冗余。检查当前可用模板；适用时用 createQuoteFromTemplateAction，然后按盘点结果调整、分组。模板缺停用产品或结构不适用时说明并使用其他受支持流程，不强制套用。
2. 操作名是 crm_describe_operation / crm_prepare_operation 的 operation 值，不是独立 MCP 工具。参数以服务器描述为准。createQuoteRoomAction 的 form.names 支持换行/逗号分隔，一次最多 30 个平级分组；新增设备使用 addQuoteItemAction 或适用的批量添加操作。已有设备分组优先使用下面的专用批量操作。每次写入遵循主 Skill 的前置版本、requestKey 与审批要求。
3. 产品从实时库选择，核对启用状态、完整型号、颜色、协议、套装构成、单位及供应商后缀。同名不同型号不能随意替换；找不到匹配产品时报告缺项/候选，不编造 ID 或私自新增产品。
4. 新增使用系统产品价格；模板/已有单据保留其价格快照、折扣和服务费配置。只在用户明确指定时通过已有业务操作调整价格；历史价差可提示，不用众数自动覆盖，不反推成本、不设毛利目标、不为贴满预算涨价或加设备。
5. 服务费、有效期等沿用公司/模板/已有单据设置。新增行的计费属性按当前业务操作默认与本次明确要求处理；不因名称含“总线”就关闭服务费，也不一律排除所有线材。不另加施工/调试/设计费行，除非本次明确要求并确认与服务费无重复。
6. 更新明细可能要求完整字段；读取现值并保留未改字段。尤其区分新增 salePrice、更新 listPrice、读取 listPriceSnapshot / salePrice 和成本快照，不能把数据库字段直接当写入参数。
7. 改版优先使用业务版本流程并保留原单；只改指定字段时不另建多张单。需要删除时可申请审批并等待，不自行批准，也不默认以重建/改名旧单绕开受限操作。状态沿用或新建草稿，未经用户要求不标已接受、已发送或已结算。

## 已有报价批量分组（能力 v1.2.0）

纯分组不要使用 updateQuoteItemAction；它是完整设备编辑接口，可能重置历史单价/折扣。不要删行重建，也不要改产品库 category。

1. 读取 crm_get_record(quotes, quoteId)，保存 version、全部 itemId、现有房间及数量/单价/折扣/服务费/备注等原值。依据本次要求与上述搭配偏好生成分组映射，不把未知设备一律塞进系统模块。用户明确要求整理时直接执行；只有确实无法判断的分类需要澄清。
2. 用 crm_describe_operation 查询以下操作的实时 schema（参数在顶层 input，**不是 form**）：
   - **applyQuoteGroupingAction**：整单建组/复用、分配、排序一次完成。`groups` 顺序就是分组顺序，`itemIds` 顺序就是组内顺序。默认 `unassignedPolicy:"error"` 要求覆盖每个现有 itemId，既不能遗漏也不能重复。`createMissingGroups:true` 自动建缺少的组，重用同名组；同名组存在歧义时拒绝。原有空组保留并排在后面，不删除。
   - **assignQuoteItemsToRoomsAction**：局部批量移入已存在的房间；只改指定条目的 roomId，所有原排序与未指定条目保持原样。roomId 为 null 才表示明确移入未分配。
3. 整单重排用 error；确实只整理一部分且要创建/排序分组时可用 `keep`：遗漏条目仍留在原房间（原本未分配的继续未分配），相对顺序保留，排在显式排序条目后。不要把 keep 理解为清空原分组。
4. 以一次最新报价 precondition 准备一个操作，READY 后直接 execute。相同请求重试保持原 requestKey、input、reason、preconditions；超时先查 operation_status，SUCCEEDED 不重复写入。新的整理意图或版本冲突后重做使用新 requestKey，不能永远复用“报价ID+分组”固定键。
5. SUCCEEDED 后读取返回的 groups/itemCount/unassignedCount/subtotal/saleTotal，再回读报价取得最新 version。核对全部 itemId、数量、单价、历史折扣、服务费、备注保持原值及目标分组顺序。金额用 CRM 返回值，PDF/Excel 沿用系统导出。不将准备成功或超时当作保存完成。

整单操作的 input 示例（ID 为占位，必须换成实时记录）：
```json
{"quoteId":"真实报价ID","groups":[{"name":"系统模块","itemIds":["设备行ID1"]},{"name":"智能面板","itemIds":["设备行ID2","设备行ID3"]}],"createMissingGroups":true,"unassignedPolicy":"error"}
```
局部移组 input 示例：
```json
{"quoteId":"真实报价ID","assignments":[{"itemId":"设备行ID1","roomId":"真实房间ID"}]}
```

连接验证时仅 describe 这两个操作并核对 schema，不试改业务单据。如果服务器暂未提供它们，刷新能力再查；仍不可用时说明需更新服务端，不退回可能改价的完整编辑接口。已知接口后正常整单整理为读取→准备→执行→回读，不逐条提交。

## 交付前回读

操作 SUCCEEDED 后用 crm_get_record 回读，检查：

- 各空间需求已映射到设备，图示、建议和待确认数量区分清楚；暂估项与缺项有说明。
- 分组顺序、同组汇总数量、产品型号/单位、套装组成一致；既无不必要重复，也未跨楼层或不同计费条件错误合并。
- 电源、网关、执行器、驱动、面板、传感器、窗帘及配件的依赖已检查；没有资料的容量/兼容性仍标待确认。
- 实际保存数量与拟定清单一致，金额及服务费读取 CRM 返回值；若无返回汇总，使用现有详情/预览/导出核对，不另写一套成本算法。发现保存差异先查原因，不把拟提交内容当已保存结果。
- 向用户交付真实报价链接、配置概要、分组、CRM 总额及必要的暂估/待确认清单。客户版 PDF 使用 crm_export_link 和系统模板，不包含成本、毛利或内部资料。

## 简短示例（示例数量不能当实际项目数据）

- 平面图没有开关点位：先按玄关、客餐厅、卧室入口/床头等列建议控制位置，再选键数；不能声称按图数出了固定面板只数。
- 示例客厅 2 块、主卧 3 块同款面板，统一系统分组且价格属性相同：报价“智能面板”内合并为 5 块，保留空间分配依据；若要求分楼层或型号不同则分别列行。
- 示例一窗双层纱布、各一条独立电动开合轨道：暂按两套驱动配置核对；对开布帘两片不自动再翻倍。无尺寸时轨道米数待确认或明确暂估。
- 模板与历史线材计费不同：保留所选模板/已有单的属性，只提示差异；金额计算交给 CRM，不执行文档里的统一计费覆盖。


## 客户导出的独立显示选项（Skill 1.17.0 / MCP 1.12.0）

`crm_export_link` 的报价 PDF 和 Excel 共用显示选项，均为严格布尔值，仅支持 `module:"quotes"`。字段省略默认 true；客户 Excel 应明确关闭内部核算。用户只要折后金额时：

```json
{"module":"quotes","id":"<报价ID>","format":"pdf","showUnitPrice":false,"showOriginalPrice":false,"showFinalTotal":true,"showItemSubtotal":false,"showRoomSubtotal":false,"showDiscount":false,"showFeeBreakdown":false,"showInternalCalculation":false}
```

Excel 将 format 改为 excel。showOriginalPrice 包括产品标价、标价合计及整单折扣前设备金额；showFinalTotal 包括已设置折扣、服务费和调整后的最终金额；showItemSubtotal 是销售单价乘数量；showRoomSubtotal 是房间设备小计；showDiscount 显示产品折扣和整单优惠；showFeeBreakdown 显示服务费、计费基数及调整。按用户选择独立传 true/false，即使不显示最终金额也可显示房间小计。只需清单时全部金额及内部核算字段设 false。
